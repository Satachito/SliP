# Play Store に出す手順

`Android/` は提出できる形になっています。残っているのは、**私にはできない 2 つ**
— 署名鍵の作成（パスワードを決める必要がある）と、Play Console への
アップロード（あなたのアカウントでの操作）— と、その周辺です。

以下、上から順に。

---

## 0. 事前に一度だけ

- **Google Play デベロッパーアカウント**（登録料 25 USD、一回払い）
- **本人確認**。個人の場合、住所・電話番号の確認に数日かかります
- **プライバシーポリシーの URL**。このアプリは何も収集しませんが、URL 欄は
  必須です。`slip.828.tokyo/Privacy.html` が既にあるので、それが使えます

---

## 1. アップロード鍵を作る

**これはあなたが実行してください。** パスワードを決めて入力する操作なので、
私は代わりに実行しません。

```bash
keytool -genkeypair -v -keystore ~/keys/slip-upload.jks -alias slip -keyalg RSA -keysize 4096 -validity 10000
```

- 保存先は**リポジトリの外**にしてください（`~/keys/` など）。`.gitignore` には
  `*.jks` を入れてありますが、そもそも中に置かないのが安全です
- パスワードは 2 つ聞かれます（ストアとキー）。同じでも構いません
- **このファイルとパスワードを失うと、同じアプリを更新できなくなります。**
  Time Machine とは別に、パスワードマネージャなどへ控えてください

### Play App Signing について

Play は既定で「アプリ署名鍵」を Google が保管し、あなたが作るのは
「アップロード鍵」だけ、という方式です。上で作るのはそのアップロード鍵です。
万一なくしても、Play のサポート経由でアップロード鍵は再登録できます
（アプリ署名鍵は再発行できません）。この方式のままにしておくのが無難です。

---

## 2. `Android/keystore.properties` を作る

Gradle はここから署名情報を読みます。**このファイルは `.gitignore` 済み**で、
リポジトリには入りません。

```properties
storeFile=/Users/s/keys/slip-upload.jks
storePassword=（1 で決めたストアのパスワード）
keyAlias=slip
keyPassword=（1 で決めたキーのパスワード）
```

このファイルが無い場合、release ビルドは**署名なし**で通ります（壊れません）。

---

## 3. AAB をビルドする

```bash
cd Android && ./gradlew :app:bundleRelease
```

できるもの: `app/build/outputs/bundle/release/app-release.aab`

Play は APK ではなく **AAB** を受け取ります。`assembleRelease` で作れる APK は
実機確認用と考えてください。

**確認済み:** R8（コード縮小）を有効にした release ビルドを実機で動かし、
JNI のエントリポイントが削られていないことを確認しています。イメージは
debug 12 MB → release 4.5 MB、AAB で 5.0 MB です。

## 4. Play Console での作業

### 4.1 アプリを作る

「アプリを作成」→ 名前 `SliP`、既定の言語、**アプリ**、**無料**。

**パッケージ名 `tokyo.sat.slip` は最初のアップロードで確定し、以後変更できません。**
変えるなら今です（`app/build.gradle.kts` の `applicationId` 一箇所）。

### 4.2 ストアの掲載情報

| 項目 | 用意したもの / 案 |
|---|---|
| アプリ名（30字） | `SliP` |
| 簡単な説明（80字） | 式をそのまま書ける電卓。2πr も cosπ も、書いたとおりに答えます。 |
| 詳しい説明（4000字） | 下の草案を参照 |
| アプリアイコン 512×512 PNG | [`AppStore/Play/icon-512.png`](../AppStore/Play/icon-512.png)（iOS のアイコンから生成） |
| フィーチャーグラフィック 1024×500 | [`AppStore/Play/feature-1024x500.png`](../AppStore/Play/feature-1024x500.png) |
| スマートフォンのスクリーンショット（2〜8枚） | [`AppStore/Play/`](../AppStore/Play) に 2 枚 |

**詳しい説明の草案:**

```
SliP は、式を書いたとおりに答える電卓です。

2πr も cosπ も、そのまま打てます。掛け算は × のまま、円周率は π のまま。
変数を置き、関数を書けば、電卓はそのまま小さなプログラミング言語になります。

・電卓モード ― 1 行に 1 つの式。1 行目の書き間違いが 6 行目の答えを隠しません
・プログラミングモード ― トップレベルの式を順に評価します
・キーボードに無い演算子は、専用のキーパッドから直接打てます
・整数は 64 ビットのまま。丸めません

同じインタプリタが、ブラウザ・macOS・iOS でも動いています。
https://slip.828.tokyo

・広告なし
・アプリ内課金なし
・ネットワーク通信なし。計算はすべて端末内で完結します
```

### 4.3 画像素材について

アイコンとフィーチャーグラフィックは、どちらも iOS のアートから
[`Android/icon.py`](icon.py) と [`Android/feature.py`](feature.py) で生成しています。
作り直したいときはスクリプトを直して再実行してください。ワードマークは
サイトの `font-family: fantasy` に合わせて Papyrus で組んでいます。

フィーチャーグラフィックは Play が端を切る場合があるので、絵と文字が四辺から
100px 以上内側にあることをスクリプトが毎回検算して出力します（現状 L118 T154
R158 B155）。

### 4.4 スクリーンショットについて

同梱の 2 枚は 1080×2400 で、エミュレータ実機から撮ったものです。Play は
縦横比の上限が緩いので通るはずですが、弾かれた場合は 1080×1920 に切り出すか、
16:9 相当の AVD で撮り直してください。

**プログラミングモードのスクリーンショットは入れていません。** サンプル本文が
電卓モード向けで、プログラミングモードで走らせると 1 トークンずつ評価されて
掲載向きの絵にならないためです（言語としては正しい挙動です）。載せるなら
`( 'double = '( @ × 2 ) )` のような本文で撮り直すのが良いです。

### 4.5 アプリのコンテンツ（審査で必ず聞かれる項目）

このアプリの実態に沿った回答:

| 質問 | 回答 |
|---|---|
| プライバシーポリシー | `https://slip.828.tokyo/Privacy.html` |
| 広告 | 含まない |
| アプリのアクセス権 | 制限された機能なし（ログイン不要） |
| コンテンツレーティング | ユーティリティ / 全年齢。暴力・性的表現・ユーザー間交流のいずれも「なし」 |
| ターゲット層 | 13歳以上（子ども向けではない、と申告するのが単純です） |
| データセーフティ | **データの収集なし・共有なし**。マニフェストに権限を 1 つも宣言しておらず、`INTERNET` すらありません |
| 政府アプリ | いいえ |
| 金融商品 | いいえ |

データセーフティの申告は自己申告ですが、`AndroidManifest.xml` に
`<uses-permission>` が 1 つも無いことが裏付けになります。

### 4.6 リリース

いきなり製品版に出さず、**内部テスト**トラックに 1 度上げることを勧めます。
自分の端末に Play 経由で入れて、署名済みのビルドが実機で動くことを確かめてから
製品版に昇格させる、という順です。

内部テスト → クローズドテスト → 製品版、と段階があります。個人アプリなら
内部テスト → 製品版で十分です。

## 5. 2 回目以降の更新

`app/build.gradle.kts` の `versionCode` を**必ず増やして**ください。同じ値は
受け付けられません。`versionName` は表示用なので、`C++/SliP.hpp` の
`SLIP_VERSION` に合わせておくのが分かりやすいはずです。

```kotlin
versionCode   = 2
versionName   = "2.1.2"
```
